# Contracts

Three open-mint shielded test tokens, `stkA`, `stkB` and `stkC`, for the Offer Files
stagenet market. They have no value; anyone can mint any amount.

The generated contracts have the shape of the reference's `SSTAR` row
(`contracts/generated/SSTAR.compact`), which the reference deployed on stagenet. A diff
against `SSTAR.compact` shows only the domain, name and symbol values, plus header lines.
Each contract has:

- `domainSep()`, `kind()`, `decimals()`: pure constants (domain `stk:stka` / `stk:stkb` /
  `stk:stkc`, kind 1 = shielded native, 6 decimals);
- `tokenColor()`: `tokenType(pad(32, domain), kernel.self())`;
- `mints()`: how many mints the contract has made;
- `publishMetadata()`: emits the three MIP-0018 `mip-0018:token-metadata[v1]` events
  (name, symbol, decimals), once only;
- `mint(recipient, amount, nonce)`: **open**, not owner-gated, `amount > 0`; creates one
  shielded coin of the token's colour for `recipient`.

### Why generated contracts, not the parameterised `NativeShieldedToken`

The reference's parameterised `NativeShieldedToken.compact` builds its metadata events
from ledger fields at runtime. Its `publishMetadata` is k=19 (467,284 rows, about a 134 MB
proving key) and its `setMetadata` is k=19. The generated contracts write every metadata
byte as a compile-time literal, so `publishMetadata` is k=7. The emitted event bytes are
identical. The reference made the same choice (its question Q13) and deployed only
generated contracts on stagenet.

**Deviation from spec 00052 FR-001 ("Owner = the funding wallet"):** the generated
contracts have no `Ownable` owner. In the template the owner gated only `setMetadata`,
which these tokens do not have. `mint` is open in both versions.

## Build

compactc **0.34.0** (language 0.26.0, runtime 0.19.0), from the LFDT-Minokawa release
archive `compactc_v0.34.0_aarch64-unknown-linux-musl.zip`, SHA-256
`d3e292c4f48e257dcd6b3d3e3e4743d7d8ea0729f48953eab91a366d44cd026d`
(x86_64: `compactc_v0.34.0_x86_64-unknown-linux-musl.zip`,
`775ccddf5a71399835329bbf7471ba5a8c54fcc825d372c75e19ba7042069584`). ZKIR v2 (the default,
as the reference deployed).

```sh
scripts/compile-docker.sh           # compile into contracts/managed/<name>/
scripts/compile-docker.sh --check   # fresh compile in a temp tree, diff against managed/
```

`managed/` is committed **in full**, including `keys/` and `zkir/*.bzkir`, so deploying and
minting do not need the compiler. This differs from the reference, which leaves keys out
because its k=19 keys are 134 MB. Here the largest file is the k=14 `mint.prover`
(5.2 MB) and the whole tree is 24 MB. midnight-js' `NodeZkConfigProvider` checks every key
and `.bzkir` against the compiler's `compiler/contract-manifest.json`.
